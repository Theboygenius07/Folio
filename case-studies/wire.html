Case study / 003

Building Wire: a payment page from one sentence

Type what you're selling and get back a checkout link, a QR code and a live sales dashboard. Paste any API and an AI agent can use it. Built in one hackathon sprint for APIConf 2026.

2026Product design and front end

01

Intro

Wire is 2 products on one engine. Flow is for people selling something: describe the sale in a sentence, on the web or over WhatsApp, and Wire builds the payment page. Relay is for people building AI agents: paste a raw curl command or an OpenAPI spec and get back tools an agent can call straight away.

Wire was built for the APIConf 2026 hackathon. The result: a seller goes from one sentence to a live checkout link with no code and no invoice setup, and a developer hands an agent a new API without writing a tool schema by hand.

Each section below takes one piece of Wire apart and puts the working version on the page, ported from the repo with its own numbers.

Where it works. On the web and over WhatsApp for sellers, and in any MCP client for developers, Claude Desktop and Cursor included.

02

Every API becomes the same shape

Wire rests on one type, 48 lines long. It says what a tool is: a name, a description, a typed input schema, and a handler that makes the real HTTP call. Everything else in Wire either makes that shape or uses it.

Paystack's 6 operations are written in that shape by hand. Relay's compiler writes it for you, from a curl command or an OpenAPI spec. On the other side, 2 things consume it: an MCP server that any agent can connect to, and one agent loop, runAgent, which hands the tools to OpenAI's Responses API and calls whatever the model asks for, for up to 6 turns.

Flow is that loop pointed at Paystack. Connect is the same loop pointed at a seller's own Airtable or Notion, run once after each sale with 4 turns and a prompt that says "doing nothing is a correct outcome."

Where it lives. lib/gateway/types.ts holds the shape, compile.ts builds it, lib/openai/agent.ts runs it, and lib/mcp/server.ts serves it. None of them knows whether a tool was compiled or written by hand.

03

Say what you're selling

Flow's page asks one question: what are you selling? The box answers it for you while you think. It types an example at 35 milliseconds a character, holds it for 1.8 seconds, deletes it at 18 milliseconds a character, waits 0.4 seconds, and starts the next. There are 5 examples, from a party with 2 ticket tiers to a single ebook.

A placeholder can't animate, so the box doesn't swap one. It runs a chain of timeouts that sets the placeholder text a character at a time, and the chain stops the moment you type, because the placeholder isn't visible then and there's nothing left to show. Enter sends what you wrote.

The arithmetic. An example of n characters lasts (n − 1) × 53 + 2,200 milliseconds. The longest has 82 characters and lasts 6.5 seconds. The loop of 5 takes 24.3 seconds.

04

One of 4 shapes

Behind the box, the agent has one decision to make before it touches Paystack: which of 4 shapes the sentence describes. One price. Several named tiers. A subscription, if the words say so. Or none of them, because the price is missing, in which case it has to ask rather than guess.

Each shape has its own script. One price creates an invoice, plus a reserved bank account for transfers if Paystack will give one. Tiers call nothing at all: each tier's payment link is made later, when a buyer picks it. A subscription skips the bank account, because recurring billing only works off a card. A missing cap is fine and becomes 100. A missing price is not.

One decision never goes to the model. The comment in the code says it plainly: "a seller's payout routing isn't something an LLM should decide". Neither tool's schema mentions the split. It's spliced onto the call in code, after the model has chosen what to make.

Uniqueness. The page's reference and its customer email are made in code as well, because, in the code's words, "an LLM is not a reliable source of uniqueness."

05

A dashboard that ticks

What comes back is a checkout link, a QR code that points at it, and a dashboard. The dashboard asks the server for the record every 3 seconds and says so at the top. It shows sold against cap, revenue in naira, and the share of the cap, over a lime bar.

The numbers swap in place. The bar slides: Tailwind's transition-all at 500 milliseconds, so each new sale moves it along instead of jumping. Wire's design guide has a line for it: "Nothing snaps instantly."

The last line on the card closes the loop. If the seller has connected their own system, a small agent acts on it after each sale, and the dashboard says what it did, like "Reduced stock count by 1." The seller sees their stock sheet change from the same page that shows the money.

  1. It works in WhatsApp.

    Messages arrive through Twilio. Each one is signature-checked and de-duplicated by its message ID, then the same engine runs with 3 tools: create a sale, edit one, or refund a payment. It replies in plain words, and the prompt sets the tone with one line: "Sold 12/100 so far, ₦60,000 in." A new sale's QR code follows as an image captioned "Scan to pay".

  2. It talks to what you already use.

    On Connect, paste the address of your stock sheet or database and Wire compiles it into tools. After each sale it updates your system, and it's fine if nothing applies.

    06

    Paste a curl, get a tool

    Relay is the compiler with the lid off. Paste a curl command and it reads the flags people actually paste: the method, each header, the body, a user for basic auth, and the URL. Anything else is ignored rather than rejected. The parser's own comment states the goal: "paste what you copied from devtools".

    An Authorization header becomes the auth kind: bearer, basic, or a raw API key. Other headers, apart from Content-Type, become required inputs. Each field of a JSON body becomes a typed input, numbers as numbers, true and false as booleans, anything else as a string. The tool is named from the method and the path, so a POST to /v1/things becomes post_v1_things. Paste OpenAPI JSON instead and the same box notices. There's no toggle.

    The figure below runs the parser line for line. Whatever it makes is served as an MCP server, so Claude Desktop, Cursor or your own agent can call it. The playground streams the agent at work as server-sent events: reasoning, tool_call, tool_result, then done or error.

    Where the secret goes. The token from an Authorization header never enters the schema. It's kept as authValue and added to each request by the handler, so the model never sees it.

    07

    Dots that notice the pointer

    The design rules fit in one short guide. One loud colour per view. Dotted grids behind anything that's product. Hairline borders, no shadows. Light mode only, on purpose. The lime only appears where it means something: the main button, a live dot, the progress bar, the highlighted words in a headline. Headings are PP Neue Montreal and body text is Saans.

    The dots come in 2 behaviours. On Relay's hero they brighten. Each dot breathes on its own sine between 0.05 and 0.28 opacity, and within 160 pixels of the pointer it rises toward 0.85 and grows to 1.6 times its size. The pointer itself is eased, 12% of the way each frame, so the bright patch trails behind it. Dots behind the headline are held at 70%, fading back to full over 48 pixels.

    On the home page, inside the product cards and behind the dashboard, they repel: anything within 130 pixels is pushed up to 60 pixels away and springs back. It replaced the particle and spotlight hover cards of the first version. With reduced motion on, the breathing stops and the repel switches off.

    Where they run. Brighten on Relay's hero and the developer page. Repel on the home page, inside product cards, and behind checkout, Connect and the dashboard.

    08

    What changed on the way

    Hackathons are mostly changing your mind quickly. Here is what changed between the first version and what runs now.

    First versionNow
    The productOne product, FlowPay2 products on one engine, Flow and Relay
    StorageA flat JSON file on one serverUpstash Redis
    The cardsParticle and spotlight hover effectsA dot grid that moves out of your way

    The storage note. The first version's store was "deliberately a flat JSON file, not a database: this only needs to survive a single demo session on one running server." Upstash Redis is what lets Wire run on serverless, where each request can land on a different machine.

    09

    Conclusion

    Wire was built in a day and a half, but the idea underneath it is simple enough to outlast the sprint: describe an API once, and both a seller and an agent can use it. Flow is that idea for people who'll never read an API doc. Relay is the same idea for people who write them.
